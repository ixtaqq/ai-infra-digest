## Slice 1a: `/coverage TICKER [days]`

### What it does

New Telegram command. Queries `articles` for rows where `affected_stocks` contains the given ticker, within the last N days (default 14, matching "bullish for two weeks" from the incident), ordered newest-first. Renders each article's date, impact (Bullish/Bearish/Neutral), impact score, and reason — directly answering "is coverage of this ticker trending bullish or bearish, and why."

### Implementation

- `src/index.ts` — new `registerCommand("coverage", ...)` handler, modeled directly on the existing `/thesis` and `/sec` handlers (same file, same patterns: `ctx.text.split(...)`, `supabase.queryRows<T>(...)`, `escapeHtml()`, try/catch returning a plain-text fallback message).
- `src/utils/supabase.ts` — no new method needed; use the existing generic `queryRows<T>("articles", params)` with params: `` `affected_stocks=cs.{${encodeURIComponent(ticker)}}&created_at=gte.${encodeURIComponent(cutoffDate)}&select=title,summary,impact,impact_score,reason,created_at&order=created_at.desc&limit=15` ``. `cutoffDate` computed via `todayInTimezone(config.app.timezone)` minus N days (or a plain `Date` arithmetic + `.toISOString()`, consistent with how other date-range queries in this codebase are built, e.g. `processor/thesis.ts:66`).
- No migration. No new table. Zero schema risk.

### Command usage

- `/coverage NVDA` — last 14 days (default)
- `/coverage NVDA 30` — last 30 days
- No results → `"No recent coverage found for NVDA in the last N days."`
- Ticker missing → usage hint, matching the style of `/watchlist`'s usage hint

### Tests (per Test Review — command handlers get real coverage now, not deferred)

New `src/index.test.ts` (or extend an existing handler-test file if the 4A test-extraction work below creates one) covering the extracted, testable command logic:
- ticker + results found → renders chronological list with impact/score/reason
- ticker + zero results → "No recent coverage" message
- missing ticker → usage hint
- Supabase not configured → existing "not configured" message pattern
- default 14-day window vs explicit `days` argument override

### Failure modes

| Codepath | Realistic failure | Test? | Error handling? | User sees |
|---|---|---|---|---|
| `queryRows` network/HTTP error | Supabase down or timeout | Yes (new test) | Existing try/catch → generic "Could not fetch" message | Clear error, no crash |
| Malformed ticker input (e.g. `/coverage ''`) | Empty string after uppercasing | Yes (new test) | Falls through to "missing ticker" branch | Usage hint, not a crash |
| `affected_stocks` array containment syntax typo | PostgREST returns 400 | Covered by the network-error path above | Same generic fallback | Clear error, no crash |

No critical gaps — this reuses an already-hardened query/render pattern from three other commands.

## Slice 1b: Thesis Evolution History

### Schema (new migration, additive only)

```sql
CREATE TABLE IF NOT EXISTS ticker_thesis_history (
  id BIGSERIAL PRIMARY KEY,
  ticker TEXT NOT NULL,
  bull_case TEXT NOT NULL,
  bear_case TEXT NOT NULL,
  confidence INT CHECK (confidence BETWEEN 1 AND 10),
  key_drivers JSONB DEFAULT '[]'::jsonb,   -- matches ticker_theses's existing column type (outside-voice finding #2)
  week_of DATE NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(ticker, week_of)
);

CREATE INDEX IF NOT EXISTS idx_ticker_thesis_history_ticker_week
  ON ticker_thesis_history(ticker, week_of DESC);

ALTER TABLE ticker_thesis_history ENABLE ROW LEVEL SECURITY;

-- Same pattern as ticker_theses (outside-voice finding #1 — this was missing
-- from the design doc and would have made the dashboard milestone silently
-- return empty data forever).
CREATE POLICY "public_read" ON ticker_thesis_history
  FOR SELECT TO anon USING (true);
CREATE POLICY "service_role_write" ON ticker_thesis_history
  FOR ALL TO service_role USING (true) WITH CHECK (true);
```

No retention policy added to `data-retention.yml` — decided against (see Architecture decisions below): this table's entire purpose is to be the history everything else prunes away.

Naming note: this table is **insert-or-overwrite-per-week**, not append-only (outside-voice finding #4) — a same-week re-run overwrites that week's row via `on_conflict=ticker,week_of` + `resolution=merge-duplicates`, which is correct for idempotent cron retries but means there's no audit trail of same-week regenerations. Documented here so a future reader doesn't assume true append-only semantics.

### Implementation

- `src/processor/thesis.ts` — inside `generateTheses()`, after the existing `upsertTickerTheses(theses)` call (line 233): compute `const weekOf = todayInTimezone(config.app.timezone);` and call a new `supabase.insertTickerThesisHistory(theses, weekOf)`. Independent, best-effort — log and continue if it fails, no transaction (matches this codebase's existing Supabase-write philosophy elsewhere).
- `src/utils/supabase.ts` — new `insertTickerThesisHistory(theses, weekOf)` method, following the exact `supabaseFetch(...)` + `on_conflict=ticker,week_of` + `resolution=merge-duplicates` pattern already used for `stock_prices` (`on_conflict=date,ticker`).
- `src/index.ts` — `/thesis TICKER` handler: query `ticker_thesis_history` for the last 6 rows by `week_of DESC`. **If 0 rows returned** (regression-fix, mandatory — see Code Quality finding #3), fall back to the existing single-row `ticker_theses` query exactly as today. If 1-5 rows, show whatever exists (no special-casing needed beyond the existing "show whatever exists" logic). Display `week_of` next to each snapshot and its confidence (outside-voice finding #3 fix: shows the real gap if a cron run was ever skipped, cheaper than gap-aware delta math).
- `website/dashboard/index.html` (separate, later milestone) — timeline card, one batched query for all tracked tickers (`ticker=in.(...)`, mirroring the existing `sec_filings` batch-fetch pattern at `processor/thesis.ts:111-115`), confidence-delta computed client-side from raw values, `week_of` shown alongside.

### Architecture decisions from this review

| # | Decision | Chosen | Why |
|---|---|---|---|
| 1 | Where is `week_of` computed? | Inside `generateTheses()` | No signature change, no caller update; matches `generateDigest()`'s own-runDate pattern |
| 2 | Does `/thesis NVDA` always show history? | Yes, with 0-row fallback to `ticker_theses` | Directly matches the workflow this feature exists for; a separate subcommand would add friction to the exact case it's solving |
| 3 | Dashboard timeline query shape | One batched query (`ticker=in.(...)`) | Matches existing `sec_filings` batch pattern; avoids 10x round-trips on a 60s-auto-refresh card |
| 4 | Retention on `ticker_thesis_history`? | None | Trivial volume (~520 rows/yr); pruning would defeat the point of a history feature |
| 5 | Confidence-delta gap safety | Show `week_of` next to each snapshot | Cheapest fix for the outside-voice's skipped-cron-run finding; explicit dates beat implicit gap-detection math |

### Failure modes

| Codepath | Realistic failure | Test? | Error handling? | User sees |
|---|---|---|---|---|
| History insert fails, `upsertTickerTheses` succeeds | Network blip on the 2nd write | New test required | Logged, continues — `ticker_theses` (latest) still updates correctly | No user-visible impact this week; history just doesn't gain a row |
| `/thesis NVDA` queried before any history exists (week 1) | New table, zero rows | New test required (this is the regression-fix path — **critical**, was the #3 Code Quality finding) | Falls back to `ticker_theses` | Sees today's exact behavior — no regression |
| RLS policy missing (if migration is written without it) | Dashboard queries return `[]` silently | N/A — this is a migration-completeness check, not a runtime test | No error thrown by Supabase — this is the danger | Empty dashboard card, no error to debug from (outside-voice finding #1 — now fixed in the migration above) |
| Skipped Sunday cron run | `week_of` gap between snapshots | Manual/visual check via displayed `week_of` | `week_of` shown next to each entry | Sees the real dates, catches the gap themselves — no silent mislabeling |

### Tests

Extend `src/processor/thesis.test.ts`:
- `generateTheses()` calls `insertTickerThesisHistory` with the computed `weekOf` alongside the existing `upsertTickerTheses` call
- History insert failure is logged and doesn't prevent `upsertTickerTheses` from succeeding (independent-writes contract)

New coverage for `src/index.ts`'s `/thesis` handler (part of the same test-extraction work as `/coverage`, per the 4A decision):
- ticker + ≥1 history row → chronological list with `week_of` shown
- ticker + 0 history rows → falls back to `ticker_theses`, identical output to pre-change behavior (the regression test)
- no ticker → top-5 by confidence, unchanged
